# 创作画布与长时间规划排查

## 现象与证据

线上“御剑观光”项目在排查时有 38 个节点，其中 18 张分镜图、2 条旧视频。旧视频没有 shot_ids，也没有引用新增分镜。问题是方案缺少绑定，不是图片没有生成。补图阶段保护了旧成片，却没有另外建立分镜版视频方案。

2026-09-20 19:00 后只读统计（北京时间，部署前快照）：

| 阶段 | 次数 | 累计耗时 | 单次中位数 |
| --- | ---: | ---: | ---: |
| 分镜图片任务 | 30 | 132.3 分钟 | 4.0 分钟 |
| 场景图片任务 | 18 | 44.5 分钟 | 1.2 分钟 |
| 规划 | 39 | 23.1 分钟 | 30.8 秒 |
| 审阅 | 58 | 20.5 分钟 | 11.5 秒 |

媒体耗时包含等待、恢复和保存，并非纯 GPU 推理时间；各阶段可能重叠，不能把累计时间直接当作用户墙钟等待时间。起飞和菌塔远景各生成 5 次，浮空岛生成 4 次。存在真实的姿态/比例缺陷，也有把参考已有护手、背景物件误认为新增缺陷的审阅误判。

补六条视频的现场规划还复现了单段流式输出超过 32 万字符。原实现先等待长输出失败，约 246 秒后才转分段；分段也没有字符硬上限。该次请求失败后旧项目仍被完整保留。

上线有界分段后，本次实测在约 200 秒到达第六个节点，但最终编译仍出现 `IndexError`。回归测试复现：视频 `shot_ids` 多于 `storyboard.shots` 时，压缩前的分镜引用编译先按索引访问，再做全图校验，导致正常的字段修正流程没有机会运行。修复为在单节点验证及引用编译入口均校验镜头 ID 与分镜数量；分段当场重试当前节点，保留其他已完成分段。

再次实测还发现：分段完成后的一处引用错误，会先触发整图纠错，额外输出约 5.8 万字符并引入其他镜头数量错误。分段草案现在直接进入已有的单节点修复协议，保留其余待提交修改；每节点最多三次、整轮最多八次，耗尽不提交错误方案。回归测试同时覆盖局部修复成功和耗尽时保护原方案。

## 改动

- 全屏画布覆盖应用窗口，Esc 或按钮退出；保留原缩放、滚动、选择和布局。审阅以可收起浮层打开。
- 全图缩放同时考虑宽高，支持定位节点；显式引用的资产即使不在对话附件列表也有节点和连线。
- 视频项目中的未绑定分镜显示数量和“补齐视频依赖”，通过正常规划生成真实 shot_ids/references/depends_on，保留旧成片。
- 继续一键生成保留返工次数与反馈，避免暂停后重新从早期失败节点开始；已删除节点的记录不带入新运行。
- 自动执行可指定 target_node_ids，包含其所有上游依赖，不执行范围之外的后继视频。未完成运行恢复范围；显式空列表开始全项目执行。用于先完成分镜，再生成视频。
- 图片审阅返回 revise 时，使用原始候选和真实参考独立复核一次；确认缺陷仍返工。复核不是人工确认，也不能保证消除模型误判。
- 16 个及以上节点的大画布整体修改直接分段；单节点返工保留原快速路径。清单/单节点/整体输出分别限制为 16000/32000/64000 字符，超限不提交半份 JSON，关闭模型 HTTP 流后转入有界恢复。

## 验证与发布

单元测试覆盖全屏退出与轮询保留、远节点定位、资产连线、分镜绑定请求、暂停恢复的公平调度、限定范围不提交视频、复核保留真实缺陷、大画布直接分段、超长流停止并释放 HTTP 连接。

发布包含 Agent、Gateway、Web 和 Android Web OTA；不涉及原生 Android 改动，无需新 APK。实际生成速度仍受单张约四分钟的服务任务时长约束，模型返工次数不能承诺归零。

## 线上操作锁回归修复

用户再次反馈全屏等操作无反应。此前仅测试普通状态/生成状态与本地页面，漏测未结束的前端请求，不能视为完整线上交互验收。真实控制器复现：打开项目后等待资产元数据会一直占用 busy；所有画布点击也经过同一 perform 操作锁，被静默忽略。

修复将全屏、缩放、选择、定位和布局操作与模型/媒体请求锁隔离，且导航完成不会错误释放仍在进行的提交锁。项目详情返回后即可编辑，资产元数据异步补全；失败提示保留且不会再次锁住页面。两条回归测试在旧代码失败，修复后通过，覆盖慢请求期间全屏/缩放/审阅、重复提交保护、延迟资产失败后仍可交互。

本次局部测试 65 通过；完整 scripts/test.sh：Go vet/test/build 通过、Python 1322 通过、Web 345 通过；Android 原生单测因缺少 Java/SDK 跳过。线上点击验收尚待浏览器连接恢复，不能以文件哈希检查代替。

线上项目 v4383 已完成六条分镜版视频方案：44 节点、18 张分镜、8 个视频节点（2 条旧成片+6 条新方案），18 张分镜全部具备真实依赖及 shot_ids 映射；本轮耗时 264208 毫秒。原 38 节点及状态逐项不变，新视频未提交生成。

## 空字段导致的自动返工误拦截

后续监督发现：落日分镜因真实构图问题需要返工，模型规划已经正常返回，却被 Gateway 报“自动方案试图改动已确认内容”。本地用线上 44 节点快照模拟 Python 零修改返回，同样复现，排除了这次错误由模型越界修改造成。新建视频节点的空 `revision_suggestions` 在 Go 保存时省略，Python 返回 `[]`，严格节点比较把 nil 和空数组当成不同内容；局部返工还会锁定这些无关的未确认视频，因此中断整个自动任务。

修复在节点反序列化边界统一空 suggestions，不放宽实际内容保护。新增单元测试覆盖 null、空数组无改动，以及非空候选变化仍拒绝；旧代码空数组分支失败，修复后通过。另以真实项目快照做零修改往返，全部返工锁定节点逐字段保持一致。临时快照诊断不提交仓库。

受影响 Go 模块及完整 scripts/test.sh 通过（Python 1322、Web 345，Go vet/test/build）；Android 原生测试仍因缺少 Java/SDK 跳过。本次仅 Gateway 解码、单元测试与文档，不需要 OTA。浏览器实测补充：44 节点快照、资产请求持续未完成时，全屏占满窗口，定位选中放大至 75%，Esc 退出并恢复原视图；生产浏览器会话仍超时，不能据此宣称生产点击已验收。
