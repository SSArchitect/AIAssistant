# 长任务体验（第一阶段）

## 用户行为

- 聊天中的生图、生视频、深度研究使用统一任务卡，位于“执行过程”下方、回答或产物上方；实时生成、恢复和历史消息使用同一顺序。任务卡展示真实阶段、已用时间、最近状态更新时间，以及默认开启的提醒开关。移除卡片的 Trace 跳转；服务返回明确的 `progress_percent`（0–100 数字）和 `queue_position`（从 1 开始的整数）时，直接显示进度条与排队位置，否则只展示阶段，不猜测百分比或排队名次。
- 页面中下方采用 44px 悬浮圆形“后台任务”入口，默认位于输入区上方。仅存在进行中（含排队、等待授权）或未读终态任务时显示；全部完成且已读后隐藏，并收起展开的浮卡。支持鼠标和触屏拖动，超过 6px 视为拖动，拖动结束不触发打开；取消拖动恢复原位置。位置按浏览器持久化，刷新恢复；窗口尺寸或输入区变化时限制在工作区内，浮卡自动选择上下展开并避免越界。角标优先显示未读数，没有未读时显示进行中任务数。点击后在圆按钮上方展开独立任务卡片浮层，不占用正文高度；点击外部、键盘焦点离开或按 Esc 收起，Esc 将焦点送回入口。点击“跳转至会话”回到原会话。长任务不阻塞其他会话；同一会话执行期间仍禁止再提交新一轮，输入区会提示切换会话或开启新话题。
- 图片和视频展示服务实际返回的排队、生成、恢复、保存状态；研究展示计划、检索、证据整理、核验、报告和归档阶段。普通聊天超过 30 秒也会进入任务列表。
- 浏览器刷新、切换页面或锁屏不会取消服务端执行。重新打开后从服务端恢复状态和结果，恢复过程中不重新 POST 生成请求。
- 完成后在原会话展示产物；在其他页面时显示可点击的站内提醒。提醒开关和已处理状态按账号保存，重新打开应用也可获知此前已追踪任务的完成情况，不重复提醒历史任务。
- 所有新任务默认开启提醒，卡片开关明确显示“提醒已开启 / 提醒已关闭”。阶段变化、队列位置变化、每 10% 的生成进展和资料整理进展形成持久化未读高亮；重复轮询和时间流逝不会反复提醒。进展更新只高亮动态列表，终态继续使用站内完成提示。可以逐项或全部标为已读，打开任务会话也会确认该项更新；关闭提醒时清除未读并静音后续更新，重新开启不重放旧提醒。已完成的结果在当前可见会话中读到后自动标为已读，同时清除对应弹窗；已读终态按账号持久化，后续轮询和刷新不再提醒。仅阅读进行中进展不会取消后续完成提醒。未读任务优先排序，关闭列表不会清除未读。
- 研究资料整理单独展示“已整理 n / N 组资料”，进度条仅表示这一阶段，不代表整份报告的完成度。
- 当前提醒是站内提醒，应用未打开时不发送系统推送。通知设置属于当前浏览器，不跨设备同步。

## 生命周期

`AgentEngine.process` 使用 task-local context 发送 `media.task.progress`，相互并发的账号/任务不会共享进度回调。嵌套工作流的媒体进度归属外层执行，任务摘要合并相关子 run 的研究事件，避免把子步骤完成显示为主任务完成。

Spark 普通 HTTP / 非流式调用继续使用原来的图片 240 秒、视频 540 秒等待期限。流式聊天中的 Spark 媒体任务在此期限后继续查询原任务，最多追踪 6 小时；等待、下载及网络恢复都计入上限。已取得 Provider task ID 时直接 GET 原任务；提交结果尚不明确时沿用原始请求体和同一幂等键。明确失败、过期、参数或鉴权错误不会重新生成。治理层只延长生图、视频和研究工具的流式后台期限，权限及调用次数限制保持执行。

`wait_timeout`、连接中断和下载问题不能证明生成失败，卡片显示“结果尚未确认”；生成已完成而下载遇到短暂问题会自动继续取回原产物。系统停止等待不代表 Provider 已取消计算，因此不提供虚假的“取消生成”按钮。

Gateway 保持现有的浏览器断开后接收并保存结果行为。Agent 的 SSE subscriber 断开时也不取消其执行任务；停止向已断开的 subscriber 缓存 token，最终结果仍进入 TraceStore，可由原有会话恢复逻辑读取。

## 持久化与 API

- TraceStore 在服务启动时启用 SQLite，默认 `data/agent_traces.db`，可用 `AGENT_TRACE_STORAGE_PATH` 配置。运行记录和事件分别存储，避免每次事件重写全部历史。
- 当前仍由单个 Agent 进程拥有执行任务。进程重启会把未完成记录标记为 `interrupted`，保留输入、事件和媒体任务标识；不会自动重放研究或重新提交媒体生成。跨进程断点续跑不属于此阶段。
- `GET /api/tasks` 经 Gateway 使用当前登录账号查询 `GET /agent/tasks`，返回紧凑根任务摘要，包含全部运行中任务和最近 50 个终态任务；活跃任务不会因历史分页被挤出。摘要剔除原始工具参数和模型上下文，完整细节仍通过已有 run 接口获取。
- 前端每 5 秒查询摘要，页面隐藏或断网时停止查询，返回/联网时立即恢复。查询失败保留最后状态并提示重连；过期账号的响应被丢弃。
- Gateway 仅向任务浮钮返回属于当前账号真实会话的执行。Pulse 预计算、JSON 修复及其他使用内部会话 ID 的系统任务不进入提醒；用户在真实会话中主动讨论或调用 Pulse 不受影响。已删除会话的任务也不再展示。
- 任务本身、输入和结果的访问继续使用现有账号隔离。账号数据删除同时删除对应持久化 run 和事件。

## 验证

新增 `tests/test_long_tasks.py`、`tests/test_long_tasks_web.js`，并扩展 Python API 与 Go bridge/handler 测试，覆盖持久化、重启中断、并发账号隔离、同一 Provider task 超时续查、后台期限上限、断开 subscriber 后继续执行、根/子任务合并、过期账号响应、通知去重和静音、HTML 转义及暂时断网恢复。后续测试还覆盖默认提醒状态、未读持久化/已读/账号切换、进度变化去重、面包屑展开、移除 Trace 入口、真实排队/进度字段透传及无效数据兜底。

测试使用本地临时数据库和 HTTP mock，不提交真实 GPU 生成。测试 fixture 为 trace 数据配置独立临时目录。

局部验证后运行 `./scripts/test.sh`。生效需要重启 Agent 和 Gateway，并加载更新后的前端静态资源。
