# 创作工作区

导航中的「创作」以创作项目为默认入口，提供对话、产物画布、模板和资产，独立于 Super Chat 会话。原有有序工作流编辑保留在「工作流编辑」。

## 对话与产物画布

1. 描述创作想法，上传素材或引用资产。项目会自动保存，对话规划在后台运行，离开页面后可继续查看。
2. 创作导演默认使用配置中的对话模型；火山 Agent Plan 默认模型为仅支持文字的 `glm-5.3` 时，带图创作自动改用同一服务的 `doubao-seed-2.1-turbo`，纯文字创作与全局默认设置不变。其他 Plan 模型明确返回不支持图片时，只允许同服务视觉模型回退一次；自定义端点不跨服务回退，也不静默丢弃图片。创作导演读取素材预览、当前方案、已选候选与模板库，提出文本／图片／视频节点及依赖。图片先缩成最多768像素的预览；视频仅提供元数据，不声称理解视频内容，也不作为生成参考。
3. 模型处理常规参数，至多给出两个有实质影响的选择题；也支持自由输入。未解决的问题会阻止媒体生成。默认先产生方案，不自动提交付费图片或视频。
4. 确认简报后可生成主视觉候选，选用其中一张并确认。点击节点后可多选修改方向，或在「补充修改方向」自由输入，点击「按这些方向优化」交给创作 Agent。简报侧重主线、动机与情绪，分镜侧重节奏、动作、运镜、连续性、对白和声音；通常提供10个候选（先展示6个，可展开更多），优先展示模型结合节点内容给出的建议。也保留手动编辑。建议本身不会修改内容、批准节点或生成媒体，提交后才同步受影响下游并重新审阅；失败时保留选项和输入以便重试。
5. 视频必须依赖已确认的脚本文本和所用图片节点。确认参考关系后，才能点击「确认生成视频」。本次提交明确展示图片数量或视频时长；当前没有接入可靠报价／耗时估计，不展示编造的金额。
6. 画布支持拖动节点排布，连线实时跟随；拖动空白区域平移，滚动和缩放浏览，Alt+方向键可移动聚焦节点。「自动排列」恢复依赖布局。松手自动按账号/项目保存位置，刷新或重新打开可恢复；保存失败有明确提示与重试入口。布局单独保存，不改变内容版本、审批或历史快照，规划期间也可整理画布。连线区分内容依据、身份、风格与首帧等用途。窄屏将对话和画布上下排列。生成产物进入网盘资产，失败和停止时已经完成的产物仍然保留。

桌面项目页占满可视区域：左侧对话／规划与输入区固定，右侧画布、节点审阅和生成历史独立滚动。左侧按用户请求分轮次，关联节点名称、请求、规划活动和结果；旧轮次默认折叠，用户主动展开／折叠在轮询时保留。失败提示只在所属轮次显示一次，重试沿用该轮请求与目标节点。

已有画布的修改使用字段级 `patch`，只返回变更节点的变更字段；服务端合并后仍执行完整图、素材和分镜校验，再原子保存并重新进入审核。未变更字段／节点保留；视频执行 prompt 由 storyboard 编译，不重复占用模型上下文。修改轮次关闭模型额外深度思考，保持资料工具循环和正常活动进度。规划使用300秒无活动超时，实际模型输出／工具进展续期，绝对上限15分钟；Gateway留出15秒收尾时间。超时取消底层请求，保留原方案，Trace记录超时原因。

导演接口 `/agent/creation/plan` 只提出结构化方案，没有媒体执行工具和审核权限。视频复用 `video_prompting.py` 的分镜 skill 与确定性编译器。中文审阅脚本和适配模型的结构化分镜一起保存；生成时再次编译并核对提示词，避免提交内容偏离已冻结方案。当前媒体能力仍使用配置中的 Spark 服务，由导演在实际支持的模式中选择，不虚构其他可用模型。

先确定交付意图，再决定节点数量：Panel 是语义动作段，Logical Shot 是连续镜头组，视频节点是一次生成/一个文件。要求完整 15 秒单片时，多 Panel/多镜头组仍放在一个视频节点里。较长故事或明确需要多个片段时可拆成独立节点；超过单片能力且用户要求一个文件时先给出精简或分段选项，不能自动改变交付数量，也不承诺当前尚未提供的自动拼接。

复杂分镜的中文审阅稿包含制作简报、素材贡献与统一规则、角色与连续性锁、Panel、Logical Shot、无空档主时间线和执行锁；技术版由同一 `storyboard` 保存，tool 层校验时间覆盖并编译。具体字段与长度约束见 [视频提示词与分镜](video-prompting.md)。这些是产品内创作 Agent workflow 与视频工具的能力，不是 Codex 个人 skill。

缺少的角色人设与场景参考先成为图片节点，相关视频等待它们生成并确认。明确的文字服装和道具要求优先于参考图，并说明保留与修改的特征。指定为画风权威的主视觉只决定画风，不自动成为精确首帧；身份设定图的三视图、色板、编号等载体内容不进入成片。

火山官方 Agent Plan 的创作调用单独预留16384输出 token（已有显式额度保留），不改变普通对话配置。Provider 保留 `finish_reason`；被长度上限截断的方案不会当作完整方案解析，也不在同一额度下盲目重写。格式诊断只记录错误位置、类型、长度和校验消息，不记录素材、原始回复或凭证。

### 服务端审核与版本

- `CreationProject` 保存对话、资产引用、方案和每个产物节点的版本、候选、选择及审核状态。模型不能写审核状态；客户端也不能通过提交完整状态绕过审核。
- 方案更新采用稳定节点 ID。只改变修改节点及依赖它的下游版本，保留独立分支的确认；主视觉候选变更同样使下游重新进入待审阅。
- 审核接口要求当前项目 revision，旧页面操作返回409；生成还会校验上游与自身审核、未解决问题以及账号运行并发限制。
- 原始参考图的身份／风格用途使用 `reference_to_video`，即使只有一张。只有明确标记 `first_frame` 的单张图片才走首帧模式，不按图片数量猜测用途。
- 审核记录图片内容摘要。文件在网盘被修改后必须重新确认；生成提交进一步冻结输入摘要，执行时若文件再变更则停止该任务。
- `CreationProjectVersion` 保存最近可查看的历史方案和确认状态；媒体运行保存整个提交快照。后来修改项目不会改变旧任务，过期任务结果只保留在生成记录中，不覆盖新方案的候选。
- 同一项目消息／生成请求的 request_id 用于重试去重，生成不会因重复点击产生第二个任务。后台规划失败保留原方案与用户消息，原始异常不暴露给前端。
- 重启中断规划与执行，不自动重提媒体；已检查点保存的部分媒体会恢复到对应节点。当前仍是单进程 Gateway 调度。
- 项目可保存为 `project_template`，保留内容结构与依赖，清除直接资产绑定，复用时交给导演重新匹配素材。现有工作流和节点效果模板也会提供给导演。

### 项目 API

所有 Gateway 接口要求当前账号 session，忽略请求中的伪造用户 ID：

```text
GET/POST /api/creation/projects
GET      /api/creation/projects/:id
POST     /api/creation/projects/:id/messages
POST     /api/creation/projects/:id/review
POST     /api/creation/projects/:id/generate
GET      /api/creation/projects/:id/versions
POST     /api/creation/projects/:id/template
```

消息和生成返回202后由前端轮询；`messages` 接受用户文本、选定节点和资产 ID，不能接受客户端提供的模型历史或系统指令。规划调用进入 Agent Trace，成功调用的用量计入 `creation_director`。

创作导演按「读取进度 → 识别缺口 → 调用工具补资料 → 形成方案 → 等待审阅」运行一个独立的 Agent loop。工具白名单仅包含当前账号的 `search_drive`、`read_drive`、`ls_drive`，复用已有 Drive skills；用户上下文由 Gateway 注入，模型不能改变账号。每轮最多 8 次模型调用／8 次只读工具调用，单工具 25 秒、整轮 300 秒，最终方案最多自动修正一次。生成和批准仍通过画布接口处理，规划工具不能直接生成媒体。

Gateway 使用内部 `POST /agent/creation/plan/stream`（NDJSON）接收真实阶段事件，写入项目文档，浏览器约每 2.2 秒读取进度。事件只包含处理阶段、检索动作、方案接收字符数与耗时，不展示模型原始推理或未校验的 JSON。进度轮询只局部更新卡片，不重建对话和画布；仅在用户停留对话底部时跟随新增内容，向上阅读后保留对话与外层页面位置，恢复输入框焦点也不触发滚动。发送时立即显示提交状态；规划卡默认展开，完成后自动折叠，仍可手动展开查看。失败与重启中断保留为对话记录，提供重试入口。旧请求或其他账号的进度无法覆盖当前项目。

## 手动工作流编辑

1. 新建工作流，或从「分镜 → 短片」「原图 → 二次创作」模板开始。
2. 添加图片或视频节点，填写提示词、画幅，以及图片数量或视频时长。
3. 在「参考图片」中选择前面图片节点的全部产出，或选择已上传的图片资产。
4. 保存并运行。离开页面后服务端继续生成；重新进入可查看最近 30 次运行记录。
5. 工作流可以整体保存为模板，每个节点也可以保存为生图／视频效果模板。模板复制节点、提示词和参数，重新生成节点 ID、重建依赖；不会绑定原工作流的私人资产。

现有预设包括产品摄影、动漫人物、Q 版人物和电影感运镜。效果模板属于本应用的可编辑参数与提示词预设；人物风格复用 Spark 对应的版本化 Provider 模板。

## 执行边界

- Gateway 校验、持久化并执行有序工作流；Python `/agent/creation/node` 直接复用现有 image/video service，不经过聊天模型或意图路由。当前统一使用配置中的 Spark 地址和 Key。
- 每个工作流 1–20 个节点。图片节点可产出 1–9 张图片，逐张调用 Provider；视频节点产出一个 1–15 秒视频。画幅支持 16:9、9:16、1:1。
- 图片节点最多一张参考图片；视频支持 0 张（文生视频）、1 张（首帧生视频）或 2–9 张（多图参考视频）。多图是视觉参考，不承诺按顺序拼接为逐镜头视频。
- 节点只能引用前面图片节点，不允许循环、前向引用或视频作为图片输入。多个上游图片节点可汇入视频节点。
- 每个账号同时运行一个工作流。运行开始冻结定义，修改草稿不会改变正在执行的节点。
- 提交幂等键按运行、节点和产出序号区分；已完成图片立即归档。失败停止后续节点，已有资产保留。手动再次运行会创建新运行，并从头生成。
- 停止操作等待当前提交完成并归档，随后停止后续生成。服务重启将 queued/running/stopping 标记为 interrupted，不自动重复付费提交。当前仅支持单进程 Gateway 调度。

## 资产与网盘

- 为当前账号复用或建立网盘根目录中的「资产」文件夹。
- `DriveItem` 是唯一文件内容来源；`CreationAsset` 只存 Drive ID、来源、运行／节点和 Provider 任务 ID。生成结果与用户上传媒体存入同一文件夹。
- 「从网盘归入」将已有媒体文件移动到资产文件夹，保留原 Drive ID 与内容，不复制文件。
- 读取资产时，自动登记资产文件夹及子文件夹内的媒体文件。删除网盘文件后，对应资产不再出现在列表中；历史运行仍保留产出记录。
- 上传支持 PNG/JPEG/WebP/MP4/WebM，检查内容签名，最大 64 MiB；生成视频归档同样最大 64 MiB。节点引用图片最大 16 MiB，支持 PNG/JPEG/WebP。
- 媒体预览支持 HTTP Range 和账号会话鉴权。JSON 管理请求通过会话头认证；媒体元素使用会话查询参数，遵循页面的 no-referrer 设置。
- 本次自动归档范围为创作工作流的新产出；没有追溯导入历史聊天中的外部媒体链接。
- 数据表随 Gateway 启动自动迁移。账号删除同时清理创作定义、运行、资产记录及网盘内容。

- `tests/test_creation.py`：生图／视频服务契约，0/1/多图输入，风格校验，非法路径与失败响应。
- `tests/test_creation_planning.py`：真实 LLM 适配器边界（模拟响应）、一次格式修复、素材预览、模板／资产校验、分镜编译、参考用途与安全失败。
- `gateway/internal/handlers/creation_projects_test.go`：项目隔离、异步规划、审核门槛、候选选择、依赖失效、不可变快照、幂等、素材变化、模板清理与重启恢复。
- `tests/test_creation_projects_web.js`：画布布局与语义边、审核状态、项目发送重试、草稿保留、账号切换及旧编辑器与新审核按钮的隔离。
- `gateway/internal/handlers/creation_layout_test.go`：布局持久化、增量合并、重置、坐标与账号校验、与规划/审批/版本隔离；仅更新修改建议不使审批失效。前端测试同时覆盖缩放拖动、取消、点击阈值、误点抑制、保存重试、多选与自定义修改消息、草稿保留和候选转义。
- `gateway/internal/bridge/creation_test.go`：跨服务请求、响应、取消及错误隔离。
- `gateway/internal/handlers/creation_test.go`：多图到视频、图到图、部分产出、停止、重启中断、网盘关联、账号隔离和模板复用。
- `tests/test_creation_web.js` 与导航回归测试：模板深拷贝与依赖重映射、输入边界、删除引用、转义和导航接入。

局部测试后运行 `./scripts/test.sh`。自动化测试使用模拟生成服务，不调用真实的计费接口。

模型调用错误通过安全错误码传递，前端区分不支持图片、鉴权/权限、额度/限流、请求不兼容、服务连接与方案格式错误。Trace 记录对应错误类型；日志记录类型、HTTP 状态和 run ID，不记录原始 Provider 异常内容、凭据或素材。
