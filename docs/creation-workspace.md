# 创作工作区

导航中的「创作」以创作项目为默认入口，提供对话、产物画布、模板和资产，独立于 Super Chat 会话。原有有序工作流编辑保留在「工作流编辑」。

## 对话与产物画布

1. 描述创作想法，上传素材或引用资产。项目会自动保存，对话规划在后台运行，离开页面后可继续查看。
2. 创作导演默认使用配置中的对话模型；火山 Agent Plan 默认模型为仅支持文字的 `glm-5.3` 时，带图创作自动改用同一服务的 `doubao-seed-2.1-turbo`，纯文字创作与全局默认设置不变。其他 Plan 模型明确返回不支持图片时，只允许同服务视觉模型回退一次；自定义端点不跨服务回退，也不静默丢弃图片。创作导演读取素材预览、当前方案、已选候选与模板库，提出文本／图片／视频节点及依赖。图片先缩成最多768像素的预览；视频仅提供元数据，不声称理解视频内容，也不作为生成参考。
3. 模型处理常规参数，至多给出两个有实质影响的选择题；也支持自由输入。未解决的问题会阻止媒体生成。默认先产生方案，不自动提交付费图片或视频。
4. 确认简报后可生成主视觉候选，选用其中一张并确认。点击节点后可多选修改方向，或在「补充修改方向」自由输入，点击「按这些方向优化」交给创作 Agent。简报侧重主线、动机与情绪，分镜侧重节奏、动作、运镜、连续性、对白和声音；通常提供10个候选（先展示6个，可展开更多），优先展示模型结合节点内容给出的建议。也保留手动编辑。建议本身不会修改内容、批准节点或生成媒体，提交后才同步受影响下游并重新审阅；失败时保留选项和输入以便重试。
5. 视频必须依赖已确认的脚本文本和所用图片节点。确认参考关系后，才能点击「确认生成视频」。本次提交明确展示图片数量或视频时长；当前没有接入可靠报价／耗时估计，不展示编造的金额。
6. 画布支持拖动节点排布，连线实时跟随；拖动空白区域平移，滚动和缩放浏览，Alt+方向键可移动聚焦节点。「自动排列」恢复依赖布局。松手自动按账号/项目保存位置，刷新或重新打开可恢复；保存失败有明确提示与重试入口。布局单独保存，不改变内容版本、审批或历史快照，规划期间也可整理画布。连线区分内容依据、身份、风格与首帧等用途。窄屏将对话和画布上下排列。生成产物进入网盘资产，失败和停止时已经完成的产物仍然保留。

桌面项目页占满可视区域：左侧对话／规划与输入区固定，右侧画布、节点审阅和生成历史独立滚动。左侧按用户请求分轮次，关联节点名称、请求、规划活动和结果；旧轮次默认折叠，用户主动展开／折叠在轮询时保留。失败提示只在所属轮次显示一次，重试沿用该轮请求与目标节点。

左侧统一为「创作进程」，将对话、规划活动和待判断选项放在同一条阅读流里。交付形式等问题接在最新对话底部，选择后作为项目级回复进入下一轮，规划期间隐藏旧选项；也可通过输入框直接回答。输入框的「创作选项」默认收起，可选择最终图片／视频与 16:9、9:16、1:1 画幅，均允许交给 AI 判断。选择随下一条消息保存为项目 `preferences`，并透传规划与自动审阅；切换选项本身不调用模型或改写画布。未发送的选择按项目隔离，退出账号时清空，发送失败保留以便重试；有未应用选择时须先更新方案，再生成。旧客户端未传偏好时保留现有设置。

已有画布的修改使用字段级 `patch`，只返回变更节点的变更字段；服务端合并后仍执行完整图、素材和分镜校验，再原子保存并重新进入审核。未变更字段／节点保留；视频执行 prompt 由 storyboard 编译，不重复占用模型上下文。规划轮次对支持开关的模型关闭额外深度思考；Ark GLM-5.3 不支持关闭，保留其默认思考能力。保持资料工具循环和正常活动进度。规划使用300秒无活动超时，实际模型输出／工具进展续期，绝对上限15分钟；Gateway留出15秒收尾时间。超时取消底层请求，保留原方案，Trace记录超时原因。

视频执行稿先按节点检查参考绑定：以该节点真实图片顺序与职责修复 Picture/Subject 映射；工具用结构化entries填写来源图片、实际Logical Shot编号及保留方式，由程序编译三份参考定义，避免把多场景或Panel序号当作镜头编号，程序不开放镜头、时间、节点依赖或用户选择的改写。执行稿超长时，描述、参考规则与连续性说明均可精简；对白、引号原文、协议标记由程序提取并在原位置拼回，不要求模型重新抄写。参考修复和精简各最多三次，仍受整轮超时约束，已锁定节点不参与。失败分别报告参考绑定、自动精简或真实原文容量问题；旧方案的问题选项隐藏，保留用户已选回复与「重试这次规划」，避免反复询问同一方向。

OpenAI 兼容规划请求在 API 层携带严格 JSON Schema：对象关闭额外字段，所有字段必填，可省略字段在传输时允许 null。仅当模型明确拒绝支持 Schema 时，改用 `json_object`，不会退回无格式约束的输出。服务端去掉表示未修改的 null，再合并和校验；空字符串／空数组仍表示显式修改。普通聊天不受此约束影响。生成 Schema 按文本、图片、视频分支约束字段；参考来源在 node_id/asset_id 中二选一，scene_intervals 仅允许视频的场景 reference，文本没有媒体引用，图片最多三张引用。分镜时间覆盖、依赖、引用与编译长度仍由本地验证器检查。整体验证失败先修正一次，仍失败则定位草案中的问题节点，以限定节点 ID/类型的协议单独修复（每节点最多3次，整轮最多8次，仍共享15分钟上限），保留其余待提交修改。第二次回复 JSON 损坏时使用前一份完整草案，不丢弃有效修改。最终完整图通过后一次性提交；未授权图片不会通过重试绕过权限检查。持续失败报告具体节点；验证错误的字段路径和原因写入 creation.validation_failed trace，不保存原始模型回复或素材。

### 一键生成

已有画布后点击「一键生成」，即授权创作 Agent 确定剩余常规选项、审阅节点、从真实候选图中选择并依次提交媒体生成。已确认的内容与上游依赖锁定，用户已选图片继续沿用，已完成的节点不会重复生成。AI 确认结果标记为「AI 已确认」，每步简短决策依据和结果保存在可折叠活动中。

Gateway 持有执行循环和当前账号的运行预约，复用手动生成的依赖、版本、输入摘要和幂等检查。内部 `/agent/creation/review` 只返回 approve/select/revise/blocked 决策，没有修改方案或执行媒体的能力；选图提供实际预览，不能选择候选集合外的资产。方案尚有选项时，规划工具只允许处理未锁定部分。

角色混淆、候选不合格、提示词或参考职责错误等质量问题返回 `revise`。Gateway 将原因、真实失败候选、返工次数和最近反馈交给规划工具，只调整当前节点及受影响的未确认下游，重新生成、再次审阅并继续执行。失败候选保留在资产和历史运行中，不再作为本轮成品或生成参考；提示词未变时也提升节点版本，以新幂等键生成新候选。已确认及无关节点锁定，不能通过返工绕过审阅或改变交付类型。审阅发现视频缺少场景时，返工允许新增该视频或受影响下游实际引用的 scene 图片节点（count=1）；插入到视频之前，原节点相对顺序、类型、集数和已确认内容保持不变。Python 与 Gateway 都验证此范围，不允许借返工新增视频或无关图片；新增场景进入同一循环先生成、审阅，再继续原视频。循环不设固定总步骤上限，直到完成或用户停止，最近 100 条进度持续更新。不可替代的必需输入缺失、能力不支持、服务调用失败或审阅期间素材/版本变化时中止并保留内容。

图片节点没有候选时，由执行器通过依赖和输入校验后直接生成，不调用成品审阅。只有实际候选产生后才进入图像质量审阅，避免“还没出图所以需要返工”的文字循环。文本与视频执行方案仍先审阅；已经确认的图片继续复用。

自动执行从上游已确认的未完成节点中，优先选择本轮返工次数较少的节点，同次数保留画布顺序。单个场景反复返工时，不依赖它的分镜仍能推进；依赖它的分镜必须等该场景通过审阅，独立分支完成后继续处理返工节点。所有剩余节点都被未确认上游阻塞时明确报错，不会误报完成；已完成视频与已确认内容仍按原规则跳过。

返工次数与审阅反馈按未完成节点延续：暂停、恢复、重启或局部目标完成后扩大执行范围，都保留尚未完成且要求未变节点的记录；不因一次局部运行显示“完成”而归零。用户修改节点要求或更换已选参考时，清除受影响节点及下游的过时记录，保留无关分支；仅修改界面建议或再次确认同一候选不清除下游记录。自动返工调整执行提示词与参考时继续携带历史失败，避免重试策略失忆。恢复时不继承已删除或已确认节点的记录。

自动审阅只读取当前节点及上游依赖子图，移除无关节点的返工草稿、资产与模板，以及历史AI回复，避免把一次局部修改当成全项目规则。实际候选与直接参考图片分别标注资产ID、identity/environment等职责、来源节点、确认状态和预览是否可见。审阅必须对照实际参考，不能把参考已有的细节误判为新增缺陷；用户与已确认脚本的明确要求仍优先，未提及某个细节不自动构成禁令。测试覆盖无关返工隔离、真实来源标签、缺少预览不冒充已查看，以及保留视频上游。

运行期间可浏览、整理画布，内容修改等待停止后进行。「停止一键生成」取消待定审阅；已提交的媒体完成并归档后停止，不再启动下一节点。失败／停止后可点击「继续一键生成」，复用已有确认与部分产物；服务重启标记为中断，不自动重复付费请求。循环在服务端运行，离开页面不影响执行。

导演接口 `/agent/creation/plan` 只提出结构化方案，没有媒体执行工具和审核权限。视频复用 `video_prompting.py` 的分镜 skill 与确定性编译器。中文审阅脚本和适配模型的结构化分镜一起保存；生成时再次编译并核对提示词，避免提交内容偏离已冻结方案。当前媒体能力仍使用配置中的 Spark 服务，由导演在实际支持的模式中选择，不虚构其他可用模型。

先确定交付意图，再决定节点数量：Panel 是语义动作段，Logical Shot 是连续镜头组，视频节点是一次生成/一个文件。要求完整 15 秒单片时，多 Panel/多镜头组仍放在一个视频节点里。较长故事或明确需要多个片段时可拆成独立节点；超过单片能力且用户要求一个文件时先给出精简或分段选项，不能自动改变交付数量，也不承诺当前尚未提供的自动拼接。

复杂分镜的中文审阅稿包含制作简报、素材贡献与统一规则、角色与连续性锁、Panel、Logical Shot、无空档主时间线和执行锁；技术版由同一 `storyboard` 保存，tool 层校验时间覆盖并编译。具体字段与长度约束见 [视频提示词与分镜](video-prompting.md)。这些是产品内创作 Agent workflow 与视频工具的能力，不是 Codex 个人 skill。

缺少的角色人设与场景参考先成为图片节点，相关视频等待它们生成并确认。每个未确认的视频按实际地点与环境变化准备一个或多个 `purpose=scene` 图片节点，以相同画幅准备环境建立镜头，默认一个候选、无人，明确空间结构、前中后景、光线与关键环境物件。视频通过 `depends_on` 和 `references(role=reference)` 引用场景；人设或仅画风参考不能替代。重复地点可跨视频复用同一个已确认场景节点。场景节点可借用 `style`，也可通过 `environment` / `composition` 引用其他 `purpose=scene` 图片节点的真实环境与空间构图；这类引用必须声明依赖、通过普通节点审阅后再生成。仍禁止角色身份、人物/分镜节点或未分类资产冒用环境引用，也不能套用人物身份转换模板。旧项目不做批量数据迁移：下一轮规划或一键生成预检时补齐未确认视频的场景，已确认视频保持不变。新增场景会自动插到消费它的视频之前，既有节点相对顺序不变。明确的文字服装和道具要求优先于参考图，并说明保留与修改的特征。指定为画风权威的主视觉只决定画风，不自动成为精确首帧；身份设定图的三视图、色板、编号等载体内容不进入成片。

火山官方 Agent Plan 的创作调用单独预留16384输出 token（已有显式额度保留），不改变普通对话配置。Provider 保留 `finish_reason`；长度截断、未闭合 JSON、流缺少结束响应时，自动切换为「修改清单 → 每次一个完整节点」分段协议，不拼接半截 JSON。清单最多64项、每项说明最多350字符；单节点 Schema 限定本次 ID，完成的分段作为后续上下文保留。每段最多2次、整轮分段最多96次模型调用，仍共享15分钟绝对上限。所有节点补齐后再合并到原画布，执行完整依赖、素材权限、分镜和已确认内容保护校验；不逐段保存或触发媒体生成。临时连接失败和502/503/504共用最多2次退避重试（1秒、2秒），鉴权、非法请求和额度错误不盲目重试。恢复阶段和重试次数显示在创作进程，耗尽后保留原方案和已选回复。修改建议最多请求4条内容专属方向，界面继续补充至少10条可选方向；恢复时不重复生成建议或视频编译prompt。格式诊断只记录错误位置、类型、长度、模型与用量，不记录素材、原始回复或凭证。

### 服务端审核与版本

- `CreationProject` 保存对话、资产引用、方案和每个产物节点的版本、候选、选择及审核状态。模型不能写审核状态；客户端也不能通过提交完整状态绕过审核。
- 方案更新采用稳定节点 ID。只改变修改节点及依赖它的下游版本，保留独立分支的确认；主视觉候选变更同样使下游重新进入待审阅。
- 审核接口要求当前项目 revision，旧页面操作返回409；生成还会校验上游与自身审核、未解决问题以及账号运行并发限制。
- 原始参考图的身份／风格用途使用 `reference_to_video`，即使只有一张。只有明确标记 `first_frame` 的单张图片才走首帧模式，不按图片数量猜测用途。
- 审核记录图片内容摘要。文件在网盘被修改后必须重新确认；生成提交进一步冻结输入摘要，执行时若文件再变更则停止该任务。
- `CreationProjectVersion` 保存最近可查看的历史方案和确认状态；媒体运行保存整个提交快照。后来修改项目不会改变旧任务，过期任务结果只保留在生成记录中，不覆盖新方案的候选。
- 同一项目消息／生成请求的 request_id 用于重试去重，生成不会因重复点击产生第二个任务。后台规划失败保留原方案与用户消息，原始异常不暴露给前端。
- 重启中断规划与执行，不自动重提媒体；已检查点保存的部分媒体会恢复到对应节点。当前仍是单进程 Gateway 调度。
- 项目可保存为 `project_template`，保留内容结构与依赖，清除直接资产绑定，复用时交给导演重新匹配素材。现有工作流和节点效果模板也会提供给导演。

### 项目 API

所有 Gateway 接口要求当前账号 session，忽略请求中的伪造用户 ID：

```text
GET/POST /api/creation/projects
GET      /api/creation/projects/:id
POST     /api/creation/projects/:id/messages
POST     /api/creation/projects/:id/review
POST     /api/creation/projects/:id/generate
POST     /api/creation/projects/:id/automatic
POST     /api/creation/projects/:id/automatic/stop
GET      /api/creation/projects/:id/versions
POST     /api/creation/projects/:id/template
```

消息和生成返回202后由前端轮询；`messages` 接受用户文本、选定节点和资产 ID，不能接受客户端提供的模型历史或系统指令。规划调用进入 Agent Trace，成功调用的用量计入 `creation_director`。

创作导演按「读取进度 → 识别缺口 → 调用工具补资料 → 形成方案 → 等待审阅」运行一个独立的 Agent loop。工具白名单仅包含当前账号的 `search_drive`、`read_drive`、`ls_drive`，复用已有 Drive skills；用户上下文由 Gateway 注入，模型不能改变账号。正常资料循环最多 8 轮／8 次只读工具调用，输出截断后使用上述独立分段预算；单工具 25 秒，整轮采用300秒无活动超时及15分钟绝对上限，最终方案最多自动修正一次。生成和批准仍通过画布接口处理，规划工具不能直接生成媒体。

Gateway 使用内部 `POST /agent/creation/plan/stream`（NDJSON）接收真实阶段事件，写入项目文档，浏览器约每 2.2 秒读取进度。事件只包含处理阶段、检索动作、方案接收字符数与耗时，不展示模型原始推理或未校验的 JSON。进度轮询只局部更新卡片，不重建对话和画布；仅在用户停留对话底部时跟随新增内容，向上阅读后保留对话与外层页面位置，恢复输入框焦点也不触发滚动。发送时立即显示提交状态；规划卡默认展开，完成后自动折叠，仍可手动展开查看。失败与重启中断保留为对话记录，提供重试入口。旧请求或其他账号的进度无法覆盖当前项目。

## 手动工作流编辑

1. 新建工作流，或从「分镜 → 短片」「原图 → 二次创作」模板开始。
2. 添加图片或视频节点，填写提示词、画幅，以及图片数量或视频时长。
3. 在「参考图片」中选择前面图片节点的全部产出，或选择已上传的图片资产。
4. 保存并运行。离开页面后服务端继续生成；重新进入可查看最近 30 次运行记录。
5. 工作流可以整体保存为模板，每个节点也可以保存为生图／视频效果模板。模板复制节点、提示词和参数，重新生成节点 ID、重建依赖；不会绑定原工作流的私人资产。

现有预设包括产品摄影、动漫人物、Q 版人物和电影感运镜。效果模板属于本应用的可编辑参数与提示词预设；人物风格复用 Spark 对应的版本化 Provider 模板。

## 执行边界

### 图片参考的职责隔离

创作画布的图片参考 `role/note` 随提交快照保存在 `image_references`，逐项对应冻结的图片输入，并完整传给 Agent；`image_purpose` 同步保留产物职责。`style` 不代表修改原图：先由视觉模型从固定词表提取媒介、线条、明暗、配色、形状语言与质感，再按当前节点的完整提示词文生图。画风参考的原始像素、人物身份、服装与场景构图不进入 Spark 生成请求；即使旧方案误留 `character_style=chibi`，也不能覆盖 `style` 的职责。主视觉与场景属于重新构图：即使引用 `identity/reference`，也仅提取主体、外观、服装/材质、识别特征四类语义事实，按目标提示词重新生成；不将人设图作为低重绘强度底图，不继承三视图、表情矩阵或色板。当前提示词中的主体比例、动作、画风与修改要求优先；这不等于像素级身份复刻，视频仍直接接收已确认身份图片。其他用途的 `identity/reference` 保留原角色转换或原图编辑行为；没有新元数据的手动工作流保持既有语义。

场景准备在 Python 规划输出和 Gateway 自动执行预检两侧校验，模型必须创建并连线真实场景节点；一次报告全部缺少场景的视频，以便同轮修正。场景审阅明确检查环境、景别与主体占比，不能因候选包含正确角色就批准一张人设图。回归测试覆盖主视觉身份参考转为重新构图、参考提取失败不回退图生图、幂等缓存、多场景绑定与复用、旧画布插入依赖、确认内容保护及先场景后视频的执行顺序。

风格提取仅接收对应参考图及职责说明，不接收整个项目的对话或其他角色资料。固定词表禁止夹带自由主体描述。目标提示词逐字保留，按剩余 4000 字容量追加完整风格要素。提取失败不会退回图生图。准备结果按生成幂等键与完整输入摘要冻结在私有 `data/creation-image-contexts/`，不存原始图片或密钥，重试及重启沿用相同风格结果；同一键换输入会拒绝。原角色动漫化/Q版模板明确用于保留原身份，不能按“Q版画风”误用到新角色或场景。

相关回归覆盖 `tests/test_creation_image_context.py` 的风格像素隔离、身份编辑兼容、固定词表、失败前不提交及准备结果幂等；Gateway 测试验证角色职责贯穿快照与执行、无候选先生成后审阅。

- Gateway 校验、持久化并执行有序工作流；Python `/agent/creation/node` 直接复用现有 image/video service，不经过聊天模型或意图路由。当前统一使用配置中的 Spark 地址和 Key。
- 每个工作流 1–64 个节点。图片节点可产出 1–9 张图片，逐张调用 Provider；视频节点产出一个 1–15 秒视频。画幅支持 16:9、9:16、1:1。
- 图片节点最多一张参考图片；视频支持 0 张（文生视频）、1 张（首帧生视频）或 2–9 张（多图参考视频）。多图是视觉参考，不承诺按顺序拼接为逐镜头视频。
- 节点只能引用前面图片节点，不允许循环、前向引用或视频作为图片输入。多个上游图片节点可汇入视频节点。
- 每个账号同时运行一个工作流。运行开始冻结定义，修改草稿不会改变正在执行的节点。
- 提交幂等键按运行、节点和产出序号区分；已完成图片立即归档。失败停止后续节点，已有资产保留。项目图片与视频的超时、断线、下载失败及服务重启中断，在节点版本、输入哈希和冻结定义完全相同时，继续生成会复用原运行及幂等键；明确失败或修改后的节点才建立新运行。独立手动工作流再次运行仍从头生成。
- 停止操作等待当前提交完成并归档，随后停止后续生成。服务重启将 queued/running/stopping 标记为 interrupted，不自动重复付费提交。当前仅支持单进程 Gateway 调度。

### 长视频等待与续接

创作视频与聊天媒体工具共用已接单任务最长 6 小时的后台等待预算；尚未获得任务 ID 的提交仍按 15 分钟上限结束，不能宣称已接单。Gateway 比 Agent 多保留 2 分钟用于回传。已接单任务跨轮询超时、暂时断线时继续查询同一任务。

`data/creation-media-tasks/` 只持久化冻结请求摘要、服务地址摘要、Provider 任务 ID 和阶段，不保存提示词、参考图或密钥。同一生成键改变输入会拒绝，重试优先按已保存 ID 执行 GET，不再次上传或创建媒体任务。安全错误码及原任务 ID 传回 Gateway，错误明确区分等待超时、连接中断、下载失败和 Provider 明确失败，不再全部显示“节点 1 失败”。内部 `GET /agent/creation/video-task/{task_id}` 仅查询现有任务并返回状态，不提交、下载或取消媒体。

回归测试覆盖超出单轮轮询时限后继续、重启后恢复原任务、禁止修改输入重用同一键、超时错误透传，以及项目继续生成保留原运行 ID、冻结快照与输入，不覆盖不同版本。

## 资产与网盘

- 为当前账号复用或建立网盘根目录中的「资产」文件夹。
- `DriveItem` 是唯一文件内容来源；`CreationAsset` 只存 Drive ID、来源、运行／节点和 Provider 任务 ID。生成结果与用户上传媒体存入同一文件夹。
- 「从网盘归入」将已有媒体文件移动到资产文件夹，保留原 Drive ID 与内容，不复制文件。
- 读取资产时，自动登记资产文件夹及子文件夹内的媒体文件。删除网盘文件后，对应资产不再出现在列表中；历史运行仍保留产出记录。
- 上传支持 PNG/JPEG/WebP/MP4/WebM，检查内容签名，最大 64 MiB；生成视频归档同样最大 64 MiB。节点引用图片最大 16 MiB，支持 PNG/JPEG/WebP。
- 媒体预览支持 HTTP Range 和账号会话鉴权。JSON 管理请求通过会话头认证；媒体元素使用会话查询参数，遵循页面的 no-referrer 设置。
- 本次自动归档范围为创作工作流的新产出；没有追溯导入历史聊天中的外部媒体链接。
- 数据表随 Gateway 启动自动迁移。账号删除同时清理创作定义、运行、资产记录及网盘内容。

### 项目与资产库（2026-09-19）

- 创作入口显示轻量项目卡片，可搜索、重命名和删除；只有进入项目时读取画布和该项目的运行记录。手动命名不会被后续 AI 规划覆盖。
- 资产按项目归属到网盘「资产 / 项目名称」文件夹。文件夹 ID 稳定，不依赖名称；重命名同步文件夹。历史生成结果按原运行项目归档，旧上传素材按最初引用项目归档，跨项目复用仍引用同一文件。
- 删除项目会删除对话、画布和该项目运行记录，原素材移至「未归属资产」。规划或生成中的项目不可删除。
- 资产库先加载文件夹元数据，打开后按 48 项分页；支持按名称、媒体类型和来源筛选、多选和批量删除。删除操作同一事务完成，包含网盘原文件及缩略图缓存。被当前项目或工作流引用的资产、正在执行创作时的资产删除会被拒绝；未选用候选可清理并从候选列表移除。
- 图片列表、画布和生成记录使用最长边 384px 的 JPEG 缩略图。原图只在悬停、键盘聚焦或点击时加载；视频点击「预览视频」才设置媒体地址。缓存按原文件更新时间失效，返回缩略图前始终校验所属账号。
- 接口：`GET /api/creation/asset-folders`；`GET /api/creation/assets?project_id=…&limit=48&offset=0&q=…&media=image/&source=upload`；`POST /api/creation/assets/delete`（`ids`，最多 100 项）；`GET /api/creation/assets/:id/thumbnail`；`PATCH /api/creation/projects/:id`（`name`, `revision`）；`DELETE /api/creation/projects/:id?revision=…`。上传/归入接口可带 `project_id`。旧的不带筛选的资产读取接口保持兼容，创作项目页不再使用它轮询全部资产。

规划恢复回归测试：`tests/test_creation_partition.py` 覆盖长度截断、流断尾、JSON断尾、真实OpenAI兼容流协议与单节点Schema、六段视频完整恢复、局部重试、总预算、取消、已确认节点保护、素材权限校验及连接退避。所有测试使用模拟模型，不提交真实媒体任务。


### 大项目资产与多场景视频

项目资产目录与模型本轮图片预览分离：目录支持最多1024条账号内引用元数据，不限制项目资产文件夹的文件数量；单次最多读取12张图片预览，保留64MiB合计保护。编辑优先本轮附件及当前节点、引用和上游，其次原始素材；自动审阅和返工优先候选，其他节点仅带元数据，不读媒体正文。规划/审阅输入标注preview_available，不能把目录条目当成已经看过的图。所有已有节点的资产仍纳入权限与引用校验，不能为了缩小视觉输入而丢失已确认资产。

创作画布、工作流模板最多64个节点。视频支持多张场景节点同时输入，与人物及画风参考合计仍不超过9张。每个场景reference使用scene_intervals标出绝对起止秒数，全部场景时段从0连续覆盖到视频结束，不允许重叠、空档、越界或非场景引用冒用；同一连续运镜的不同Panel可以切换环境。单场景旧节点未填时段时默认覆盖全片。场景时段由程序写入已确认storyboard及执行prompt，压缩执行稿时预留这段容量，生成阶段保持同一编译结果。审阅区直接展示场景时段。

Agent先判断实际环境与参考预算，能在1–15秒、9张总参考内完成时优先单视频多场景。超限先消除重复参考，再提出叙事分段或精简方案；已授权分段且未改变明确交付约定时可自行编排。用户指定单条成片、固定集数等目标时，改变文件数量必须先确认，不自动删剧情或承诺拼接。多场景不等于多条视频。

回归覆盖50资产项目编辑、12预览上限与候选优先、非当前图片不读取、账号隔离、64节点边界、多场景完整时段校验、生成prompt一致性与容量预留、场景复用，以及前端时段展示。

### 继续一键生成与媒体接管

继续会接管本项目正在生成的节点，等待原运行结束，再审阅和推进下游；重复点击保持同一个自动控制器。失败记录会在同账号、项目、节点版本与冻结输入范围内查找原任务，优先恢复已被生成服务接收的任务，即使它被后来的失败记录遮住。已完成的新运行之后的旧失败不会被再次采用。

临时连接、查询、下载和归档异常在当前循环内最多恢复两次（2秒、4秒退避），使用原运行 ID、任务 ID 与产出序号，不重新生成已归档候选。停止立即取消退避和后续提交；正在生成的媒体仍保存结果。明确鉴权、配置或终态失败显示具体原因并暂停，不盲目重投。重复结果归档保持幂等，不清除已有审批。

回归覆盖：`creation_automatic_recovery_test.go` 验证旧任务恢复、运行中接管、重复点击、部分候选续跑、取消、恢复上限和重复归档；Python 媒体恢复与 Spark 测试验证图片任务持久化、只 GET 的恢复、HTTP 与终态错误区分；bridge 测试验证原任务标识透传。


## 2026-09-20：多参考生图与关键分镜图

产品创作 Agent 的规划/审阅工具现在按“脚本 → 人设与场景 → 关键分镜图 → 视频”准备新视频。新增 `purpose=character`，沿用 `purpose=shot_reference`；不创建 Codex 个人 skill。已存在的旧视频允许没有分镜图片，已确认节点不强制迁移；用户明确要求补分镜时只修改相应未锁定范围。新增视频通过 `require_shot_references` 契约要求镜头 ID 和至少一张关键分镜图，简单相邻镜头可共用图，不强制每个 Panel 出图。

图片最多三张参考，按 `references` 顺序冻结。`identity` 保留指定角色，`environment` 仅用于环境，`composition` 仅用于构图/姿态；`style` 仍通过有限词表抽象成文字，原始主体像素不进入生图。普通单图编辑保留旧协议；多图输入以及有参考的分镜图使用 Spark `image.reference.v1`。每个任务只出一张，候选数量由现有执行器逐次生成。分镜图禁止套用 anime/chibi 人物转换模板；超过三张输入在提交前拒绝，规划器应精简或拆分构图，不静默丢图。

分镜图同时有`environment`和`composition`时，构图/姿态参考先经过独立的语义隔离工具：只从固定词表提取本轮明确借用、原图可见且不与目标冲突的姿态、接触关系或机位/站位，原图像素不上传生成器，防止另一张分镜的背景、光色与正面人物污染当前场景。身份和环境仍以原图输入，普通单构图参考、无人的场景参考保持原有多图行为。`Picture N`按实际上传顺序重新映射，抽取后的参考标记为姿态指引；不截断原提示词。提取结果按输入摘要冻结，重试沿用，已接收的媒体任务恢复不重复提取；提取失败不回退为原图。词表不含物种、服装、道具外观、背景或色彩，无法可靠提取时不新增姿态约束，仍按目标提示词生成与审阅。

视频节点 `shot_ids` 与 `storyboard.shots` 顺序一一对应；视频对分镜图的 reference 使用 `shot_ids` 指明镜头。ID 唯一且稳定，插入镜头时保留旧 ID。程序验证来源用途、画幅、实际镜头存在性，并把 ID 映射成当前 `[Shot N]`、起止时间和 `<Picture N>`。生成图片的标签是 `Picture N`（没有视频标签的尖括号），在过滤 style 图片后重新编号。

分镜图、人设、场景一同提交视频时使用多图参考模式，总计最多九张；它们不能与精确首帧模式混用。引用与原始素材哈希仍写入生成快照，恢复已受理任务只查询原任务。用户已确认结果的保护和下游局部失效沿用现有逻辑。

自动审阅增加身份、环境、站位、动作、道具归属和设定图排版检查；质量不合格可在原返工循环中补必要的人设/场景/分镜图，禁止增加无关交付或改写锁定节点。焦点审阅只加载候选、直接选定参考与尚未完成的必要依赖；已选参考图片的旧生成输入及全项目附件目录不再一并带入。资产元数据保留用于合法引用校验。

视频审阅区显示懒加载的“关键分镜图”卡片，标明镜头、时间和确认状态，点击进入对应节点。分镜节点提供构图、站位、动作和一致性修改方向。多集子画布、独立角色/场景版本档案和资产分类筛选另行扩展，当前继续复用既有节点版本与项目资产库。

场景复用的多图执行会保留有序环境图片像素，并明确无人、单幅连续空间；不会把环境引用降级为仅抽象画风。该约束在 Python 规划和 Go 一键生成预检中一致，旧的已确认节点不强制迁移。

### 自动返工的验收依据（2026-09-21）

Gateway 在首次自动审阅图片时持久化 `review_contracts`，将创作要求与可变生成提示词分开。自动返工保留图片的 `content` 与验收基线，可以调整执行 prompt、参考和辅助节点；暂停、继续及重启不重置基线。正常用户编辑使相关节点及其受影响下游的旧基线失效，下一次审阅采用新要求，无关节点不受影响。旧项目没有基线时以当前节点初始化，不猜测恢复已丢失的历史要求。

审阅图片以冻结的创作说明为依据；只有没有说明的旧节点才回退到首次提示词。执行提示词中的参考编号、否定词和姿态技巧不会自动成为验收要求。当前参考关系和真实像素仍用于检查身份、环境与构图，其他分支草稿仍被隔离。

图片 `revise` 必须为每个被拒候选返回结构化 `findings`：候选 ID、问题分类、已有要求来源、逐字要求原文、可见问题。代码验证来源存在、原文匹配、候选覆盖，失败先要求审阅模型修正，不直接重画。返工规划接收校验后的依据和观察，不接收自由文本理由中夹带的新要求；真实质量问题仍走独立复核和返工。引用校验不等于视觉事实证明，仍需用真实合格/失败样本监督误判。

参考图的引用原文由程序按当前可见参考的固定职责填入，模型只需选择有效的 `reference:资产ID:职责`；模型抄写的参考备注不进入验收依据，避免同一参考既提供执行备注又要求引用固定职责而反复校验失败。用户要求、脚本、目标节点的引用仍逐字检查，未知／不可见参考仍拒绝，图片质量与候选覆盖要求不变。审阅 trace 记录初审／复核阶段、校验次数及稳定错误码；Schema 错误只记录类型和已知字段路径，不保存回复正文、任意字段名或上游异常原文。服务错误保留安全分类，不再全部丢成通用 error。

回归覆盖基线跨多轮返工和序列化保留、用户编辑和上游变更失效、未确认脚本与不可见参考不能作为证据、虚构要求/候选与漏检候选被拒绝，以及正常返工继续到视频的完整执行路径。

图片已有冻结验收说明时，不再把原始维护对话与历次返工聊天交给审阅模型；正常编辑仍先更新方案并使旧基线失效。图片预览保留到最长边1536像素（不放大原图），避免远处小角色在768像素预览中丢失细节。

涉及画面占比的分镜图先进行一次独立定位：只传候选像素和候选ID，不传目标尺寸、提示词、参考或既往审阅结论。模型返回角色本体与脚下实体载具的边界框，程序计算画高百分比，运动尾迹不算人物高度。定位有45秒上限；失败、空定位、多主体或不确定结果不会自动批准图片，仍需正常视觉审阅。定位框是模型估计，不能代替身份、动作、位置和环境检查；trace的`creation.review.geometry`记录边界框、计算结果和采用的区间，便于监督复核。

图片执行稿按最终提交容量计算：先预留固定指令与完整参考职责，再将超额的描述交给独立精简工具，最多三次、90秒，不直接截断。数字、Picture编号和引号原文由程序锁定并恢复，参考职责不被模型删减。结果按原始执行稿、预算与幂等键缓存，重试复用同一执行稿；原文自身超出容量时明确返回生成前错误。已被服务接收的任务只取回原任务，不重新提取参考或编译长提示词，避免取回结果也被长度校验阻断。回归覆盖拼接开销、原文保护、失败不提交、不重复整理、缓存变更拒绝与错误分类。

精简工具只返回原文中可改写的文字片段；程序保留数值及单位（例如3D、9:16）、参考编号、引号原文的顺序和位置，禁止片段重复引入这些内容。GLM规划配置复用同一服务已配置的快速视觉模型处理短工具任务，避免长推理占满整理时限。相关单测位于 `test_creation_image_prompt.py` 和 `test_creation_reference_image.py`，Gateway覆盖准备失败的稳定错误分类。

### 单视图人物参考准备

规划输入在历史资料与全部图片之后独立放置“本轮待执行任务”：手动编辑使用最后一条真实用户请求，自动返工使用当前repair，继续一键生成使用当前方案和锁定范围。历史对话保留供查阅，旧修改命令不再混同本轮指令；当前明确修改优先于冲突历史。该任务位于原始两条模型消息内部，分段规划及单节点修复均保留，不被错误输出或工具回合挤掉。

已建立的动作前置图 identity 关系在后续自动返工中持续保留：不能退化为 composition 后丢掉像素，也不能把该前置图的同一原始身份稿重新加回最终分镜。仅依据当前计划已有 identity 关系及前置图未变的身份来源做此校正；用户原有 composition、手动操作、锁定目标、身份来源变化以及不同角色的独立参考均不覆盖。原始人设仍保留在前置节点的依赖链。

分镜与角色准备节点使用identity参考时，先判断原图是否为同一人物的多视图稿。明确为多视图稿时，选择与目标机位最接近、可完整隔离的一幅现有视图，坐标必须有效且不与其他视图重叠；只裁切原像素，不重绘或修改原资产。目标需要背面但原稿没有背面时不能声称存在背面，可使用实际侧面作身份来源，目标姿态仍需生成与审阅。单视图、不同人物组合或无法确认的图片保持原输入，环境、风格和构图职责不应用人物裁切。

视图选择最多三次、60秒，按原图摘要、目标、职责和幂等键冻结坐标，不保存原始图片或密钥；重试复用同一选择，已被服务接收的任务直接恢复，不再识别或裁切。参考准备失败报告`media_reference_view_failed`且尚未提交生成。`test_creation_identity_context.py`、`test_creation_reference_image.py`和Gateway媒体桥接测试覆盖原像素保留、组合人物保护、非法/重叠区域、缓存、源上下文变化、失败不提交和恢复。

仅带一张identity参考、没有显式character_style的character准备节点也使用`image.reference.v1`，以原生单图参考生成目标姿态，不能落入默认低去噪强度的旧`image.edit.v1`。用户显式选择的动漫化/Q版模板继续按原模板执行。单视图准备只解决参考的歧义，不等于保证复杂动作、画面占比或产物质量，仍需要正常审阅与真实样本验证。

当分镜至少第三次因identity/action问题返工且确有身份来源时，创作Agent优先采用分步准备策略：复用合适的单角色动作图，或添加被该分镜直接引用的character前置节点；在无场景背景先审阅身份、目标机位和接触关系，再与原environment组合。动作前置图要求清晰可审阅，不继承最终极远景占比；最终分镜验收目标仍冻结不变。非自动、首轮、环境问题或已锁定节点不触发此策略。前置图遵循普通生成、审阅、资产保存和依赖执行，不在规划中伪称已完成。测试覆盖辅助节点真实连线、无关分支及视频数量保护。

比例审阅将“约画高10%”“约为画面高度的1/10”“约为画面高度的十分之一”等等价写法统一为同一个固定相对容差。只解释单一、明确的画面高度约数，比例范围、精确值、上下限、多主体比例或无法解析的中文数词保持原意，不扩大区间；附近其他句子的“约”不能让本句精确值变为约数。

比例定位与最后选图双向校验：明确超出原约数区间的单个候选，即便模型文字判断通过，也依据原文和独立测量返回revise，进入正常返工；多候选要求重新选择，不能因一张不合格就拒绝其他图。测量不确定、缺失或多主体时不覆盖模型决策；在区间内也不能自动证明身份、姿态或其他要求合格。tests/test_creation_review_geometry.py和tests/test_creation_review.py覆盖中文分数、数字分数、百分比、范围/精确边界、复核后的矛盾选图及多候选处理。
