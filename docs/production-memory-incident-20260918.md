# 2026-09-18 生产访问中断与 Trace 内存修复

服务器于约 08:39 起出现显著延迟，用户手动重启后于 09:57:27 恢复；域名、健康接口与 SSH 随后正常。

## 已确认的故障机制

- sysstat：08:30 可用内存约 632 MiB、交换空间使用约 994 MiB；08:46 可用内存仅约 34 MiB、交换空间使用 99.97%；09:29 可用内存约 22 MiB、交换空间 100%、CPU I/O 等待 63.90%。
- 上次启动内核日志在 08:46–09:30 连续记录 106 次内存压力提示，没有可见的 OOM kill 记录。Gateway SQL 等待由毫秒增加到 449 秒、1971 秒，网页和 SSH 同时失去响应。
- 现有记录不能识别最终触发突增的进程，不把单个创作任务或最近一次发布认定为唯一根因。

## 本次修复

TraceStore 原先在启动时加载全部历史事件。生产 trace 数据库约 267 MiB，context.built 事件合计约 178 百万字符；Agent 重启后的进程 RSS 峰值约 615 MiB，部分驻留数据随后被换入 swap。

持久化模式现在只在执行中保留完整事件；任务结束后释放大块 payload，内存中保留任务列表所需的简要事件。历史详情和分页列表按需读取 SQLite，不重新加入常驻缓存。启动时也只恢复简要事件与中断状态。完整日志、人设图上下文、已冻结的视频请求、账号隔离及重启后的媒体续接保持原有契约。未删除或改写历史素材。
